# Billy Belly Chicken: website + QR ordering prototype

Plain HTML, CSS and JavaScript. No framework, no build step. White pages with black header, footer, hero and poster sections (colours are tokens in `css/variables.css`; add the class `dark` to any section to make it a black poster). Every page has its own HTML, its own CSS file and its own JS file. English only for now (Tamil is switched off; see `js/i18n.js` to bring it back).

This is a **front-end prototype**. Data lives in the browser (localStorage), seeded from `data/*.json`. There is no server, no real payment and no kitchen screen: the waiter confirms with the customer, then tells the chef.

## Run it

**Easiest:** double-click `index.html`. It opens in your browser and everything works, including the admin and waiter pages (browsers block page scripts when files are opened this way, so the folder `js/bundles/` holds a ready-made copy that is used automatically).

**Better for real testing** (and what a live website uses): run a small local server.
```bash
python3 -m http.server 3000      # or: npx serve . -l 3000
```
then open http://localhost:3000.

If you change anything in `js/` or `data/`, rebuild the double-click copy with `npm install` once, then `npm run bundle`. A server or a host never needs this step.

## Deploy (customers can open it from anywhere)

It is a static site, so any static host works. The folder root is the publish directory.

- **Netlify:** drag the folder into the dashboard, or connect the repo. `netlify.toml` is included.
- **Vercel:** import the repo. `vercel.json` is included.
- **GitHub Pages / Cloudflare Pages:** publish the root. `.nojekyll` is included. The custom 404 only applies on hosts that serve `404.html`.
- After you have the live address: set it in **Admin > Tables & QR > Website address**, then print the QR codes. Replace `YOUR-DOMAIN` in `robots.txt` and `sitemap.xml`.

Note: demo data is per browser. A customer's order appears on the waiter screen only in the same browser (different tabs update live). To show the full flow on one phone or laptop, open the customer page and the waiter page in two tabs.

## Try this

1. Open `/order.html?table=3`, add dishes, place the order.
2. In another tab sign in as `ravi`, open My tables, table 3, tap **Confirmed with customer**, then **Mark served**. The customer tab updates live.
3. Customer taps **Request bill**. The waiter sees the alert, shows the bill, and closes the table after the customer pays at the counter.
4. Open `/parcel.html`, order, note the token (P-0xx). The waiter moves it Placed > Confirmed > Ready > Handed over.
5. Submit a review at `/review.html`. Approve it in Admin > Reviews and it shows on the home page.
6. Admin > Settings: turn the master switch off. Ordering shows a closed message at once.
7. Admin > Settings > **Reset demo data** puts everything back.


> **After you edit anything in `js/`, `data/` or any `.html` text, run `npm install` once and then `npm run bundle`.** Every page loads one ready-made script (`js/bundles/<page>.js` plus `data.js`) with a plain `<script defer>` tag, so the first screen shows at once. The same step also writes the English text into the HTML so the page is never blank while it loads. GitHub Pages, Netlify and Vercel need no build step: just upload the folder with the `js/bundles` folder included.

## How the pieces work

- **Data:** only `js/dataService.js` touches storage (`list/get/create/update/remove`). Business rules are in `js/orderService.js`.
- **Language:** English only. UI text goes through `t('key')` so Tamil can be added back later. Admin-entered content is still stored as `{ en, ta }`, with `ta` left empty.
- **Live updates:** `BroadcastChannel` between tabs in the same browser.
- **Ordering rules:** 20 s cooldown per table, duplicate-order warning, table session token (a QR scan by someone else cannot order on a claimed table), cancel only while status is Placed, multiple rounds per table with a running bill.

## Prototype to production checklist

- [ ] Backend and database (orders, menu, staff, reviews, settings). Re-implement the function bodies in `dataService.js` as API calls; the signatures stay the same.
- [ ] Real authentication: hashed passwords, signed session cookie, role checks on every API route. The current login is plain text and client-side only.
- [ ] Live updates across devices: WebSockets or server-sent events instead of `BroadcastChannel`.
- [ ] Server-side validation of prices, offers, tax, cooldown and the table session token. Never trust the browser for totals.
- [ ] Tamil and auto-translate (removed for now).
- [ ] Image upload to storage/CDN (the prototype stores small resized images in the browser).
- [ ] Replace the placeholder SVG images in `assets/images` with real photos (WebP, with width/height set) and add the real Google Maps embed address in Admin > Settings.
- [ ] Set the real domain: QR base address, `robots.txt`, `sitemap.xml`, Open Graph image, JSON-LD in `index.html`.
- [ ] Rate limiting and bot protection on order, parcel and review endpoints.
- [ ] Backups, error logging, uptime monitoring, HTTPS and security headers (starter headers are in `netlify.toml`, `vercel.json`, `_headers`).
- [ ] Privacy notice for parcel phone numbers; decide how long order data is kept.
- [ ] Test on real phones and printed QR codes, in good and poor light.

See `docs/ARCHITECTURE.md` for the page contract and API notes.

## Put it on GitHub (and a free live link)

1. Create an empty repository on github.com (no README).
2. In this folder run:
   ```
   git init
   git add .
   git commit -m "Billy Belly Chicken prototype"
   git branch -M main
   git remote add origin https://github.com/YOUR-NAME/YOUR-REPO.git
   git push -u origin main
   ```
   (Prefer no command line? Install GitHub Desktop, choose File > Add local repository, then Publish.)
3. Live site: repository Settings > Pages > Source: `main` branch, `/ (root)`. The link appears in about a minute.
